# Card and Action

## How the card is built

Fixed dark image panel on the left (optional) + two text boxes on the right (stats, milestones). Text colors come from a theme dict (`DARK`, `LIGHT`); the panel stays dark in both. Two files: `card.svg` and `card-light.svg`, chosen by `<picture>`.

- Pure SVG, no external resources (SVG inside `<img>` cannot fetch them). Embed images as base64 PNG.
- Pin ASCII characters to their grid cell with `textLength` + `lengthAdjust="spacingAndGlyphs"`.
- To win over a class rule, set `style="fill:..."` inline.
- Animation only on a small marker, with `@media (prefers-reduced-motion: reduce) { animation: none }`.
- Put a one-line explanation of the scale under the card in the README.

## Scale (honest, derived from real data)

`value = base + done * (goal_value - base) // goal` where `done = min(contributions, goal)`. The README must state the goal and what one contribution is worth. Count with GraphQL `contributionsCollection`, one aliased field per calendar year since the account was created (the API caps a window at one year).

## Workflow rules (`scripts/profile.yml.template`)

- `permissions: contents: write` only; token is `${{ github.token }}`, passed as `GITHUB_TOKEN` to the script; no other secrets.
- `cron` at an off-peak minute (not `0`), plus `workflow_dispatch`.
- `concurrency` group with `cancel-in-progress: false`.
- Bot step: `git add` the SVGs, commit only if changed, `git pull --rebase -q` **before** `git push`.
- A second job that follows the first must use `actions/checkout` with `ref: main`, otherwise it runs on the trigger SHA, which is already behind the first job's push, and its push is rejected.
- Pin third-party actions by full SHA after reading the code; add a comment with the version and date reviewed.
- The tracked SVGs are generated by the bot. After a local preview run, `git checkout` them before committing.
